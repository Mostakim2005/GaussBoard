# Base GazBoard Feature Catalog — v4.8.1

This catalog describes the product surface at Git tag `v4.8.1` only, commit `84c26437cdb998660d23d1cca37625b27e4a6213`. It is intentionally separate from the custom additions in later versions. The catalog is derived from the tagged README and source modules; it does not claim that a feature added after v4.8.1 was part of the baseline.

For the later feature history, see [`FEATURE_EVOLUTION-4.8.1-to-4.8.8.md`](FEATURE_EVOLUTION-4.8.1-to-4.8.8.md). For AI navigation, use [`INDEX.md`](INDEX.md).

## How to use this catalog

The **Where to inspect** column points to v4.8.1 modules and key entry points. For improvement work, first reproduce the behavior on a copy of a board, trace input → store operation → rendering/export, and add a focused regression check. The final column suggests areas to examine; these are investigation prompts, not claims that the base feature is defective.

## Base feature inventory

| Base capability | How it works in v4.8.1 | Where to inspect in the tagged source | What to examine when improving it |
|---|---|---|---|
| Infinite canvas, camera, zoom and pan | A world-coordinate camera maps the unbounded board to the window; a `Surface` owns canvas sizing, transforms, drawing and caches. Touch and trackpad gestures supplement mouse navigation. | `src/js/core/camera.js` (`Camera`); `src/js/core/surface.js` (`Surface`); `src/js/core/tools.js` (`Interaction`). | Camera anchoring at cursor, device-pixel-ratio changes, huge-board culling, scroll/pinch distinctions, and keeping overlays aligned. |
| Pens, pressure and saved strokes | Pointer events become ordered stroke points; strokes retain geometry, color, width and pressure. Existing midpoint smoothing draws a single centerline path in the baseline renderer. | `src/js/core/tools.js` (`Interaction` stroke handlers); `src/js/core/ink.js` (`preparePoints`, `centrelinePath`, pressure helpers); `src/js/core/render.js` (`drawStroke`). | Preserve raw sample time/pressure/metadata, latency and highlighter compositing; compare engine behavior without mutating saved stroke data. |
| Highlighter and laser pointer | The highlighter is a translucent, single-path ink style. A laser leaves a temporary, non-document trail. | `src/js/core/render.js` (`drawStroke`); `src/js/core/surface.js` (overlay and trail rendering); `src/js/core/tools.js` (input dispatch). | Verify crossings do not darken unexpectedly, laser state never enters saved objects/undo/export, and trail cleanup is bounded. |
| Partial/object eraser and stylus eraser | Partial erase cuts sample paths into surviving fragments; alternate modes remove whole objects or ink broadly. Stylus eraser hardware can select erasing behavior. | `src/js/core/erase.js` (`cutPoints`, `splitStroke`); `src/js/core/tools.js` (`Interaction`); `src/js/core/hit.js`. | Fragment geometry, timestamps and pressure preservation; locked-object behavior; touch/palm and barrel-button conflicts; undo atomicity. |
| Shape recognition and geometry | Optional straightening classifies a completed stroke and replaces it with a geometric shape only when fit error is acceptable. Shapes include common polygons, lines and arrows. | `src/js/core/recognize.js` (`recognize`, `fitError`); `src/js/core/tools.js` (`finishStroke`); `src/js/core/render.js`. | False positives/negatives, small/degenerate shapes, accessibility of the off-by-default option, and exact undo back to original ink. |
| Selection, lasso, transforms and context actions | Marquee/lasso selection feeds shared move, resize, rotate, constrain, ordering, lock, duplicate and delete operations. Context menus expose type-specific controls. | `src/js/core/tools.js`; `src/js/core/hit.js`; `src/js/core/transform.js`; `src/js/ui/contextmenu.js`. | Hit slop at zoom/DPI, touch target size, grouped/attached objects, keyboard access, lock invariants and one-operation undo. |
| Notes, text and rich text | Sticky notes and text boxes are document objects with editing, auto-fit/wrapping, alignment and handwriting/font options. Rich text is stored as text runs. | `src/js/core/tools.js`; `src/js/core/richtext.js`; `src/js/ui/textedit.js`; `src/js/core/render.js`. | Caret/selection correctness, font fallback, resize-and-wrap behavior, rich-text round trips, and safe rendering of pasted content. |
| Tables and mathematical notation | Tables store editable cells; the math subsystem loads KaTeX lazily, renders formula objects, and supports inline math spans in text. | `src/js/core/tools.js`; `src/js/core/maths.js`; `src/js/ui/mathedit.js`; `src/js/core/render.js`; `src/js/export.js`. | Clipboard fidelity, formulas during export, edit focus, offline availability, and bounded layout for long or malformed input. |
| Shapes, connectors, groups and board links | Shape/connector records live in the common document model; connector endpoints can attach to objects/groups, and board reference cards link to other saved boards. | `src/js/core/connectors.js`; `src/js/core/boardrefs.js`; `src/js/core/tools.js`; `src/js/core/render.js`; `src/js/ui/contextmenu.js`. | Endpoint movement after transforms, cycles/stale board references, grouping/deletion semantics, SVG/PDF fidelity and undo. |
| Images, clipboard, paste and drag/drop | Images can enter from the file picker, clipboard or drag/drop and render as image objects. | `src/js/insert.js`; `src/js/core/tools.js`; `src/js/core/render.js`; `preload.js`; `main.js` file/asset handlers. | File type sniffing, corrupt/oversized media, bounds, image asset identity and safe handling of external paths. |
| PDF, Word and PowerPoint imports | PDF pages render through the PDF importer; Office formats use LibreOffice when present or the built-in converter. Page selection and layout turn pages into board objects. | `src/js/importers/pdf.js`, `pptx.js`, `slideanim.js`, `slidemedia.js`; `src/js/insert.js`; `src/js/ui/pagepicker.js`; `main.js`, `soffice.js`, `msoffice.js`. | Malformed-file behavior, import memory use, page range boundaries, Office fidelity, converter availability and clean rollback on failure. |
| Paged canvas, paper backgrounds and templates | Documents can have page dimensions/background/ruling; built-in templates create reusable initial layouts. | `src/js/core/pages.js`; `src/js/core/render.js` (`drawBackground`, `drawRuling`, `pageRects`); `src/js/templates.js`; `src/js/ui/panels.js`. | Page geometry at zoom, safe conversion between page and infinite modes, export clipping, print margins, and template consistency. |
| Board library, folders, recents, search and properties | Boards are listed from local storage; folders and recent-board metadata organize them; names/tags/aliases help find and link notes. | `src/js/ui/boardpicker.js`; `src/js/core/folders.js`; `src/js/core/recent.js`; `src/js/core/boardrefs.js`; `src/js/ui/properties-dialog.js`; `src/js/ui/search-dialog.js`; `src/js/ui/panels.js`. | Search ranking and stale records, rename/move behavior, damaged settings recovery, keyboard navigation and consistency across panels. |
| Undo/redo, autosave and board persistence | `Store` owns the document state and an operation log; commits support undo/redo. The main process persists boards and assets atomically. | `src/js/core/store.js` (`emptyDoc`, `Store.commit`, serialization/load); `main.js`; `storage-location.js`; `src/js/app.js`. | Transaction completeness, schema compatibility, interrupted writes, asset reachability, migration idempotence and restore-after-crash. |
| PNG, SVG, PDF and board-file export | Export code serializes selected or whole-board content into raster, vector, PDF or `.gazboard` output. | `src/js/export.js` (`exportable`, `buildSvg`, PDF/PNG paths); `src/js/board-export.js`; `main.js` file dialogs. | Selection bounds, fonts and embedded images, multipage dimension correctness, sanitization, reproducible output and error cleanup. |
| Local files, storage location and portability | Electron main process, preload bridge and platform adapters separate privileged file operations from renderer UI; boards remain in a user-selected local folder. | `main.js`; `preload.js`; `storage-location.js`; `src/js/platform/platform.js`; `src/js/platform/web-adapter.js`; `package.json`. | IPC allowlists and path boundaries, migration between locations, portable/installed separation, permission errors and platform fallbacks. |
| LAN board sharing | Optional local-network sharing pairs devices and transfers board data through the sync protocol. | `sync/node.js`; `sync/protocol.js`; `src/js/app.js`; `src/js/ui/panels.js`; `preload.js`. | Pairing scope, transfer limits, encryption/error handling, user consent, privacy of attachments and interrupted transfer cleanup. |
| Settings, localization, accessibility and presentation | Settings and menus configure tools/appearance; UI strings come from locale dictionaries; presentation/timer tools support teaching. | `src/js/ui/panels.js`; `src/js/ui/toolbar.js`; `src/js/ui/present.js`; `src/js/ui/timer.js`; `src/js/i18n.js`; `src/locales/*.json`. | Keyboard/focus behavior, contrast, translated placeholders, screen-reader labels, settings migration and presentation exit cleanup. |
| Web/PWA and Android adapters | The same core is used with platform adapters for web storage/files/clipboard/PDF and Android integration. | `src/js/platform/`; `src/sw.js`; `android/`; `docs/PWA.md`; `android/README.md`. | Keep platform-specific behavior gated, storage permissions accurate, offline cache complete, and file workflows consistent with desktop. |

## Base-versus-addition boundary

The following are **not** v4.8.1 base features: synchronized audio-ink replay, audio-session recording and bookmarks, study tape, gesture scratch-out, split study workspace, stitched replay video, the later ribbon mobility and gallery/template tag filtering, PDF background import, page-margin guide overlay, Catmull–Rom/Bézier option, and the 4.8.8 protocol boundary fix. Their implementation and version history live in [`FEATURE_EVOLUTION-4.8.1-to-4.8.8.md`](FEATURE_EVOLUTION-4.8.1-to-4.8.8.md).

## Improvement workflow

1. Confirm the target behavior against a v4.8.1 board and the current v4.8.8 behavior.
2. Follow the relevant layer dossier in [`INDEX.md`](INDEX.md) to the input, data-store and render/export paths.
3. Record cross-feature effects: undo/redo, audio timestamps, pressure, storage/serialization, export, i18n, and other platforms.
4. Add a focused test before merging an improvement; never modify a real user's board to create test evidence.
